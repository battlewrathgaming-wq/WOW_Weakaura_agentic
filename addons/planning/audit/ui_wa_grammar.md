_Target: `Interface\AddOns\WeakAurasOptions` (WA 5.21.2 backport, Interface 30300) + `WeakAuras\Prototypes.lua`, `WeakAuras\Types.lua`. Read-only audit; files only, no conversation context. Cites are `file:line` relative to `F:\games\Ascension_wow\resources\ascension-live\Interface\AddOns\`. Written incrementally — a section without a "TRANSLATABLE AS" note is unfinished._

**Library provenance (fact first):** WeakAuras does NOT ship Ace3. `WeakAuras\embeds.xml:3-4` includes only Archivist and LibCustomGlow-1.0; `WeakAuras\WeakAuras.toc:23` lists `Ace3` under `OptionalDeps`; `WeakAuras\Init.lua:64-77` verifies via `LibStub:GetLibrary` a list that does not even name AceGUI/AceConfig. `WeakAurasOptions\OptionsFrames\OptionsFrame.lua:14-16` does `LibStub("AceGUI-3.0")`, `LibStub("AceConfigDialog-3.0")`, `LibStub("AceConfigRegistry-3.0")` unguarded — so on this client Ace3 arrives from OTHER loaded addons (copies found on disk: AceGUI-3.0 minor 33 in Bartender4/Recount/Skada/ShadowedUF_Options/PlateBuffs, minor 30 in Omen; AceConfigDialog-3.0 minors 43..54, highest = Recount `Recount\Libs\AceConfig-3.0\AceConfigDialog-3.0\AceConfigDialog-3.0.lua:7` = 54). ## 1. The option-table grammar

**Interpreter:** WA authors plain AceConfig-3.0 option tables and hands them to AceConfigDialog-3.0: `AceConfigRegistry:RegisterOptionsTable("WeakAuras", optionTable, true)` (`WeakAurasOptions\OptionsFrames\OptionsFrame.lua:1147`) then `AceConfigDialog:Open("WeakAuras", group)` into an AceGUI container it owns (`:1231`). AceConfigDialog reads the table and instantiates AceGUI widgets (`Recount\Libs\AceConfig-3.0\AceConfigDialog-3.0\AceConfigDialog-3.0.lua:1054-1405` `FeedOptions`, the reference copy on this disk). WA never draws an option pane by hand — everything on the right-hand pane is table → AceConfigDialog → AceGUI. WA's own layer is (a) the generators that BUILD the tables per aura, (b) ~30 custom AceGUI widgets, (c) a `__meta` sub-grammar it flattens before hand-off (§3).

**Shape.** One root `{ type="group", name=..., order=..., args={ key = <option>, ... }, get=?, set=?, hidden=?, disabled=? }` per tab (`LoadOptions.lua:1220-1233`, `TriggerOptions.lua:159-164`). Inside `args`, each key is a string; WA keys are dotted composites `"<group>.<optionName>"` (`CommonOptions.lua:310`), and the AceConfig `info` path (`info[#info]`) is the key (`LoadOptions.lua:1224-1226`).

## 2. Where it is fed from (Prototypes.lua args → option entries)

**Data source.** `Private.event_prototypes = { ["Health"] = {...}, ... }` (`WeakAuras\Prototypes.lua:1621`), one prototype per trigger event, indexed by display-name key; `Private.load_prototype` (`:963`) is the same schema for the Load tab; `Private.category_event_prototype[type][name] = prototype.name` (`:8869-8872`) derives the per-category sub-type dropdown. The schema is documented in-source at `Prototypes.lua:964-976`.

**Prototype-level keys** (`Prototypes.lua`, e.g. Health `:2273-2330`): `type` (category → trigger.type), `name` (L[] display; also `event_prototype.name` used for the trigger tab title `TriggerOptions.lua:303`), `args` (array), `events`/`internal_events`/`loadFunc`/`force_events`/`init`/`statesParameter`/`progressType`/`countEvents`/`delayEvents`/`timedrequired` — only `args`, `name`, `countEvents`, `delayEvents`, `timedrequired` are read by the options builder (`LoadOptions.lua:191,1077,1124,1170`).

**TRANSLATABLE AS:** the PATTERN "declarative arg schema (`name/display/type/values/enable/required/desc/width/multiline/reloadOptions/collapse/multiEntry`) → one mapper function that emits a fixed control family per `type` into a flat AceConfig `args` table with a running `order`". The mapper is ~1000 lines because WA has 12 arg types × multiEntry × specific-unit; a smaller addon needs the same skeleton (`for _, arg in ipairs(args)`, `hidden = function() return not enable(state) end`, `use_`+value pairing, `values` string → enum-table lookup) at a fraction of the size. Not portable: the spell/item/aura correction and icon lookups, `ScanForLoads`/`UpdateThumbnail`/`SortDisplayButtons` side-effects, `OptionsPrivate.IsCollapsed` persistence.

## 3. Composition (tabs, per-trigger tabs, groups, order, hidden)

**Top-level tabs are NOT AceConfig groups.** They are an AceGUI `TabGroup` WA builds by hand: `tabsWidget:SetTabs({ {value="region", text=L["Display"]}, {value="trigger",...}, "conditions", "action", "animation", "load", "authorOptions" (L["Custom Options"]), "information" })` (`OptionsFrame.lua:1201-1218`); a `"group"` tab is prepended only when the picked aura is a real group (`:1214-1216`). Tab click → `frame.selectedTab = tab; frame:FillOptions()` (`:1226-1229`). Each tab has its own generator function in a dispatch table `{ group=GetGroupOptions, region=GetDisplayOptions, trigger=GetTriggerOptions, conditions=GetConditionOptions, load=GetLoadOptions, action=GetActionOptions, animation=GetAnimationOptions, authorOptions=GetAuthorOptions, information=GetInformationOptions }` (`:1155-1166`); only the SELECTED tab's table is generated and registered (`EnsureOptions(data, tab)` → cache `aceOptions[id][tab]`, `:1151-1172`; `RegisterOptionsTable("WeakAuras", optionTable, true)` `:1147`). So the "WeakAuras" app name always points at ONE root group = the current tab; the AceConfig tree is one level deep.

**Inside a tab: the `__meta` group sub-grammar → flat `args`.** Every generator returns `allOptions = { [groupKey] = { __title=..., __order=n, __collapsed=bool, ..., <optionName> = <option>, ... } }`. Then:
1. `fixMetaOrders(allOptions)` renumbers `__order` to contiguous 1..N, ties broken by key sort (`CommonOptions.lua:318-343`).
2. `flattenRegionOptions(allOptions, isGroupTab)` (`:299-316`): for each group, base = `1000 * __order`; `addCollapsibleHeader` emits `<key>collapseSpacer` (a full-width `description`, or a `header` when `__topLine`), `<key>collapseButton` (an `execute` with `control="WeakAurasExpand"`, `image` = expand/collapse/bullet texture, `func` toggles `OptionsPrivate.SetCollapsed`), and 0.15-wide `WeakAurasIcon` execute buttons for `__add/__up/__down/__duplicate/__delete/__applyTemplate/__dynamicTextCodes` (`:91-271`; the title width shrinks 0.15 per button `:126-127`). Then every non-`__` option is deep-copied into `result["<groupKey>.<optionName>"]` with `order += base` and `hidden` wrapped as `collapsedFunc() or oldHidden()` (`copyOptionTable :273-297`).
3. Result becomes the root group's `args`.

So "sections with expanders" are ordinary options: the header is an `execute` and the body's visibility is a `hidden` closure over a collapse-state store (`collapsedOptions[id][namespace][path]`, `WeakAurasOptions.lua:2012-2054`, in-memory only, keyed by aura id and moved/removed with `MoveCollapseDataUp/Down`, `RemoveCollapsed`).

**Per-object dynamic sections (triggers).** `GetTriggerOptions` iterates `data.triggers` and asks the registered trigger system for that trigger's group: `OptionsPrivate.Private.triggerTypesOptions[trigger.type](data, index)` (`TriggerOptions.lua:104-117`), unioned as `{ ["trigger.<n>.<event>"] = options }` (`GenericTrigger.lua:553-555`); each gets `__title = "Trigger n: <name>"`, `__order = n*10`, `__collapsed = #triggers > 1`, custom `__isCollapsed/__setCollapsed` bound to a `collapsedId` namespace, and `__up/__down/__duplicate/__delete/__applyTemplate` handlers (`TriggerOptions.lua:313-420`); a trailing `addTriggerOption` group with `__order = 5000, __withoutheader = true, __topLine = true` (`:119-146`); a leading `global` group (`__order = 1`) for trigger combination (`:31-95`). Adding/removing/reordering a trigger mutates `data.triggers` then `WeakAuras.ClearAndUpdateOptions(data.id)` (`:143,336,349,357`) — the tab regenerates with N±1 sections. Delete goes through `StaticPopup_Show` first (`:380-408`). The same idiom drives Display sub-regions (`"sub.<i>.<type>"` groups at `__order = 200+i`, `DisplayOptions.lua:96-110`), Conditions, Actions, Animations, and Author options (`AuthorOptions.lua:1987-2060` — a second declarative→AceConfig mapper whose SOURCE is user-authored `data.authorOptions` with `Private.author_option_types` `Types.lua:3359`).

**Region-specific display sections** come from a registry: `Private.RegisterRegionOptions(name, createFunction, ...)` (`WeakAuras\WeakAuras.lua:513`); `GetDisplayOptions` calls `regionOptions[data.regionType].create(id, data)` (`DisplayOptions.lua:93-94`), which returns `{ [sectionKey] = {__title=L["Icon Settings"], __order=1, ...} }` (`RegionOptions\Icon.lua:8-16`), then post-processes every `type="range"` to `control="WeakAurasSpinBox"` (`DisplayOptions.lua:154-158`), and installs one root `get/set` that routes `info[#info]` (`"sub.3.subtext.text_color"` or `"icon.color"`) via `parsePrefix` to `data` or `data.subRegions[i]` (`:160-192`, `CommonOptions.lua:61-80`).

**`order` sequencing:** three tiers — `__order` (group, ×1000) → per-option `order` (integers, plus fractions like `order + 0.1 .. 0.8` for header buttons `CommonOptions.lua:141-259` and `17 + i/10` for repeated blocks `GenericTrigger.lua:434`) → AceConfigDialog sorts numerically. Nothing depends on Lua table order.

**`hidden` gating and liveness:** every `hidden` is a closure over the LIVE aura table (`trigger.type == "custom" and trigger.custom_type == ...` `GenericTrigger.lua:50-53`). AceConfigDialog re-evaluates all `hidden`/`disabled`/`name`/`desc`/`values`/`image` functions on every feed, and it re-feeds the whole custom container after every `set`/`func` (`AceConfigDialog-3.0.lua` `ActivateControl` tail: `AceConfigDialog:Open(user.appName, user.rootframe, ...)` when `iscustom`) — so visibility is live without WA doing anything. WA only intervenes (`ClearAndUpdateOptions`) when the STRUCTURE of the table must change (different arg set after `trigger.event` changes, `GenericTrigger.lua:480-484`; multiEntry count; enable-toggle flips that emit different `dummy` spacers `LoadOptions.lua:410-412`).

**TRANSLATABLE AS:** (a) tabs = hand-built AceGUI `TabGroup` + one generator per tab + `RegisterOptionsTable(app, <that tab's root>)` + `AceConfigDialog:Open(app, container)`; (b) sections = flat `args` with `__meta` pre-processing (title row as `execute`, body `hidden` = collapse-state OR own hidden, order = 1000×section + local); (c) per-object dynamic sections = iterate the object array, one `__meta` group per object with `__order = i*10`, structural changes → regenerate. All three are patterns over stock AceConfig; the collapse store, `parsePrefix`, `TraverseLeafs` are WA-specific.

## 4. Two-column layout & widths

**Constants:** `WeakAuras.normalWidth = 1.3`, `halfWidth = normalWidth/2` (0.65), `doubleWidth = normalWidth*2` (2.6) (`WeakAuras\Init.lua:7-9`). These are AceConfig NUMERIC `width` multipliers of AceConfigDialog's `width_multiplier` (170 px in the disk copy `AceConfigDialog-3.0.lua:83`), i.e. normal = 221 px, double = 442 px, half = 110.5 px. The options pane is anchored `TOPLEFT = frame.TOPRIGHT + (-63 - normalWidth*340)` (`OptionsFrame.lua:561,1198,1345`) — 340 = 2 × 170, so the pane's usable width is exactly ONE doubleWidth plus fixed margins. That is the whole grid: **a line holds 2 × normal, or 1 × double, or 4 × half, or normal + half + half, or (normal−0.2) + 0.2 icon.**

**Line filling** is AceGUI's `"flow"` layout (AceConfigDialog `FeedGroup` sets `container:SetLayout("flow")` and wraps the root in a `ScrollFrame` with flow), which places widgets left-to-right and wraps when the next widget does not fit. WA relies on exact sums: `use_` toggle at normalWidth + value control at normalWidth = one line (`LoadOptions.lua:401-403,569-571`); number arg = toggle(normal) + operator(half) + input(half) (`:503,529`); spell arg = toggle(normal−0.2) + icon(0.2) + input(normal) (`:424,705,745`); header rows = title(2.6 − 0.15×buttons) + 0.15 icons (`CommonOptions.lua:126-127,177`).

**Spacers / forced breaks:** (1) `type="description", name="", width=doubleWidth` — full-line blank, used to force the next control onto a new line (`LoadOptions.lua:254-260,366-373`; `GenericTrigger.lua:526-531`); (2) `type="description", name="", width=normalWidth` "dummy" — fills the empty second column when the toggle is off so the NEXT toggle stays in column 1 (`LoadOptions.lua:491-498`); (3) `width="full"` on the collapse spacer (`CommonOptions.lua:129-135`) — AceConfig `"full"` = `control.width = "fill"` = own line; (4) `type="execute"` with `image=function() return "",0,0 end` = an invisible button used as an "and"/"or" label-spacer between multiEntry rows (`LoadOptions.lua:476-483`); (5) `WeakAurasSpacer` widget exists (`AceGUI-Widgets\AceGUIWidget-WeakAurasSpacer.lua`) but is not referenced from an option table; (6) `WeakAurasExpandAnchor` — a 1×1 px `description` control used as an anchor point (`LoadOptions.lua:1204-1214`).

**Author-options width:** user-declared `width` is a multiplier `(option.width or 1) * WeakAuras.normalWidth` (`AuthorOptions.lua:1998,2007`) — the same two-column unit exposed to end-users.

**TRANSLATABLE AS:** the idiom is "pick a unit U (WA: 1.3 × Ace's 170 px), size the pane to 2U + margins, and author every control's `width` as U, U/2, 2U, or 0.15–0.2 for icon buttons; use blank `description`s of U or 2U as column-fillers and line-breaks; let flow layout do the rest". Requires an AceConfigDialog that honours numeric `width` (newer than the minor-54 copy on disk); the fixed-string alternative (`"half"/"normal"/"double"/"full"`) gives a coarser 85/170/340 px grid with the same pattern.

## 5. Live behaviour (refresh, getters/setters, throttling)

**Two refresh mechanisms, layered:**
1. **AceConfigDialog's own re-feed.** After any `set`/`func` through a widget, `ActivateControl` ends with `AceConfigDialog:Open(appName, rootframe, basepath...)` for a custom container (`AceConfigDialog-3.0.lua`, ActivateControl tail; `range` only on `OnMouseUp`, `color` only on `OnValueConfirmed`, `multiselect` deferred to `OnClosed`). `Open` → `container:ReleaseChildren()` → `FeedGroup` re-walks the CURRENTLY REGISTERED table, re-running every function-valued key. So getters, `hidden`, `disabled`, computed `name`s all refresh after every edit "for free". `AceConfigRegistry:NotifyChange(app)` is the external trigger for the same refresh (fires `ConfigTableChange` → `RefreshOnUpdate` next frame → `Open`); WA never calls it (0 uses in WeakAurasOptions).
2. **WA's regenerate path.** `WeakAuras.ClearAndUpdateOptions(id, clearChildren)` (`WeakAurasOptions.lua:903`) → `frame:ClearOptions(id)` drops `aceOptions[id]` (+ parent + tempGroup, `OptionsFrame.lua:1081-1095`) → `frame:UpdateOptions()` regenerates the selected tab's table and re-`RegisterOptionsTable`s it (`:1126-1149`). It does NOT itself redraw; the redraw comes from mechanism 1 (the set that called it) — or, when the change did not go through AceConfig (drag/drop, texture picker, trigger delete via popup), WA calls `WeakAuras.FillOptions()` which rebuilds the TabGroup and calls `AceConfigDialog:Open` explicitly (`:1174-1241`, comment `:1174-1179` states this rule). `frame.ReloadOptions` = `ClearAndUpdateOptions(picked, true)` + `FillOptions()` (`:1097-1102`). Both paths clear `commonOptionsCache` (`:1083,1130,1185`) — a per-refresh memo used by the multi-selection getters (`CommonOptions.lua:7-58`).

**Setter convention** (uniform across builders): `set = function(info, v) <mutate data>; WeakAuras.Add(data); [WeakAuras.UpdateThumbnail(data)]; [WeakAuras.ClearAndUpdateOptions(data.id)]; [ScanForLoads / SortDisplayButtons] end` (`GenericTrigger.lua:37-42`, `LoadOptions.lua:409-416`). `WeakAuras.Add(data)` = re-compile the aura from its saved table (runtime side); the options never talk to the runtime widget, only to `data`. Getters read `data` directly (`get = function() return trigger.custom_type end`). Root-level `get/set` with `info[#info]` are used where the key equals the field name (`LoadOptions.lua:1224-1231`, `DisplayOptions.lua:165-191`).

**Multi-selection (mass edit).** When `data.controlledChildren` is set (a group or the temp multi-pick group), the tab generator strips all per-option `get/set/hidden/disabled(/func)` (`removeFuncs`, `CommonOptions.lua:345-355`) and installs root-level `getAll/setAll/hiddenAll/disabledAll/executeAll` that iterate `TraverseLeafs(data)`, resolve the SAME `info` path in each child's own generated table, and aggregate: get → value if all children agree else nil (`:938-992`), set → apply to every non-hidden/non-disabled child inside `pauseOptionsProcessing(true)` … `false` (`:994-1041`), hidden → hidden only if hidden in ALL children unless the option flags `hiddenAllIfAnyHidden` (`:393-436`), name/desc/values → replaced with conflict-aware functions (`replaceNameDescFuncs :477`, `replaceValuesFuncs :834`). `executeAll` passes `secondCall = true` after the first child so expand toggles flip once (`:1043-1065`).

**Throttling / batching:** no timers in the options builders. Text commits happen on Enter / focus-lost (AceGUI EditBox → `OnEnterPressed` → `ActivateControl`; the `WeakAurasSpinBox` fires `OnValueChanged` while typing but `OnMouseUp` (= reload) only when `SetValue(value, reload=true)` — comment at `AceGUIWidget-WeakAurasSpinBox.lua:233-239`). Batch edits use `OptionsPrivate.Private.pauseOptionsProcessing(true/false)` + `PauseAllDynamicGroups/ResumeAllDynamicGroups` (`CommonOptions.lua:996-1036`), and `SortDisplayButtons`/`UpdateButtonsScroll` early-return while paused (`WeakAurasOptions.lua:990,1015`). Trigger `onUpdateThrottle` (`GenericTrigger.lua:76-104`) is a RUNTIME setting exposed as an option, not UI throttling.

**TRANSLATABLE AS:** "read from the model, write to the model, then re-register the (regenerated) table; let AceConfigDialog re-feed after every set" — portable verbatim with AceConfig. The regenerate-vs-refresh split (`ClearAndUpdateOptions` only when the table SHAPE changes; otherwise rely on function-valued keys) is the key pattern. Multi-selection aggregation is a WA-specific layer (needs a per-object table cache and a leaf traversal) — copyable as design, not as code.

## 7. Locale & labels (L[], code→display enum adaptors)

**L[] table.** `WeakAuras.L = {}` (`WeakAuras\Init.lua:4`); per-locale files assign `L["English key"] = "translation"` and early-return when `GetLocale()` does not match (`WeakAurasOptions\Locales\enUS.lua:3-5`); a metatable makes any missing key return itself and memoise it (`WeakAuras\Locales\enUS.lua:1640-1643`). Options files do `local L = WeakAuras.L` and use `L["..."]` for every `name`/`desc`/`values` string; the KEY is the English text. Both WeakAuras and WeakAurasOptions load their own locale files into the same table (`WeakAurasOptions\locales.xml`, 11 locales). No AceLocale.

**Enum `values` = code→display tables in Types.lua.** ~176 `Private.<x>_types = { code = L["Display"], ... }` (`WeakAuras\Types.lua`; e.g. `glow_action_types :23-26`, `hostility_types :53-56`, `operator_types :2319-2326` where display is `"="`/`"!="`, `string_operator_types :2338-2342` where the CODE is a Lua snippet `"find('%s')"` and the display `L["Contains"]`). Some are integer-keyed for a fixed order (`frame_strata_types :41-51`); some are built at load from game data (`WeakAuras.class_types` coloured via `WrapTextInColorCode` `:1186-1191`); some are derived views (`format_types_display[k] = v.display` `:1052-1053`).

**Binding points:** (1) Prototype args name the table by STRING — `values = "actual_unit_types_cast"` (`Prototypes.lua:2337`) — resolved at build time as `OptionsPrivate.Private[arg.values] or WeakAuras[arg.values]` (`LoadOptions.lua:850-854`); (2) hand-written options reference the table directly `values = OptionsPrivate.Private.custom_trigger_types` (`GenericTrigger.lua:32`); (3) `values = function()` for context-dependent lists (`TriggerOptions.lua:41-47,66-73`). Sorting is by DISPLAY text via `Private.SortOrderForValues` (`WeakAuras.lua:6153-6173`, strips the `newFeatureString` prefix before comparing) and passed as `sorting`. Saved data always stores the CODE; the display string never leaves the UI. Runtime uses the same code (e.g. `operator_types` keys are the Lua operators the trigger compiles with).

**Label conventions:** `WeakAuras.newFeatureString .. L["Count"]` prefix for new features (`LoadOptions.lua:1081`); colour escapes inline (`"|cFFFF0000 "..L["Negator"].." "..arg.display.."|r"` `LoadOptions.lua:270`); tooltip text in `desc` from L[] or `Private.*_tooltip` constants (`Prototypes.lua:2338`).

**TRANSLATABLE AS:** the "one `L` table with identity-fallback metatable + `values = "<enumTableName>"` resolved by name into a `code → L[display]` table + sort-by-display" adaptor is small, dependency-free, and directly copyable; the specific tables are WA's domain.

## 8. What is translatable

**(a) Libraries WA ships that are reusable as-is:** none of the UI stack. WA ships only `Archivist` and `LibCustomGlow-1.0` (`WeakAuras\embeds.xml`); AceGUI-3.0 / AceConfig-3.0 / AceConfigRegistry-3.0 / LibSharedMedia-3.0 / AceGUI-3.0-SharedMediaWidgets are consumed via `LibStub` from whatever else is loaded (provenance note at top; the disk copies in Bartender4/Recount/Skada/ShadowedUF_Options/Omen/PlateBuffs are AceGUI minor 30–33 and AceConfigDialog minor 43–54, no LICENSE file present in any of them; upstream Ace3 is BSD-style — verify upstream). An adopter therefore ships its own Ace3 (recent enough for numeric `width`, `sorting`, `control` on `execute`/`description`) rather than borrowing WA's. WA's own widget files are GPL-2 (§6).

**(b) Patterns to copy (grammar, not code):**
1. **Zones/tabs:** hand-built AceGUI `TabGroup` in a fixed frame; per-tab generator; `RegisterOptionsTable(app, <tab root group>)` + `AceConfigDialog:Open(app, container)`; tab select → regenerate (§3, `OptionsFrame.lua:1126-1241`).
2. **Typed controls:** stock AceConfig `type` set; `range` + `control="WeakAurasSpinBox"`-style widget for slider-with-tick (§1, §6); `execute`+`image` for icon buttons; `description name=""` for spacers.
3. **Conditional visibility:** `hidden = function() return not <predicate over model> end` closures, evaluated by AceConfigDialog on every re-feed; regenerate only on shape change (§3, §5).
4. **Per-object dynamic sections:** iterate the object array, emit one `__meta` group per object (`__title/__order=i*10/__collapsed/__up/__down/__delete`), flatten with `1000*__order` offsets and collapse-state `hidden` wrappers (`CommonOptions.lua:91-343`); mutate + `ClearAndUpdateOptions` on add/remove/reorder (`TriggerOptions.lua:100-149,313-420`).
5. **Declarative arg schema → controls:** `{name, display, type, values, enable, required, desc, width, multiline, reloadOptions, collapse, multiEntry}` → one mapper emitting a fixed control family per `type` with a running `order` (§2, `LoadOptions.lua:172-1217`).
6. **One code:user label lookup:** `L` identity-metatable + `Private.<name>_types = {code = L[display]}` + `values = "<name>"` string binding + `SortOrderForValues` (§7).
7. **Two-column grid:** unit U, pane = 2U + margins, widths U / U/2 / 2U / 0.15–0.2, blank `description` fillers (§4).
8. **Setter shape:** mutate model → recompile → optional regenerate; getters read the model (§5).

**(c) WA-specific / not portable:** the `data`/`trigger` saved-table conventions (`use_<x>` toggles, `<x>_operator`, `.single/.multi`), `WeakAuras.Add` recompilation, `ScanForLoads`/`UpdateThumbnail`/`SortDisplayButtons`/`ResetMoverSizer` side effects, `parsePrefix` sub-region routing, `TraverseLeafs` multi-selection aggregation and `commonOptionsCache`, spell/item/aura correction (`CorrectSpellName` etc.), collapse-state store keyed by aura id, `hiddenAllIfAnyHidden`/`multiTristate` (only meaningful with the multi-select layer), the Custom-Options author-mode editor (`AuthorOptions.lua`), the text-editor/code-review/import-export frames, `IsLibsOK` guards, and hard-coded texture paths under `Interface\AddOns\WeakAuras\Media\Textures\`.

**TRANSLATABLE AS:** an addon can adopt WA's grammar by (i) depending on Ace3 (own copy), (ii) writing ONE mapper from its own arg schema to AceConfig `args`, (iii) adopting the `__meta`→flatten idiom for sections and per-object groups, (iv) using numeric widths on a 2-column unit, (v) implementing a SpinBox-class widget for slider-with-tick, and (vi) an `L`+enum-table adaptor — everything else in WeakAurasOptions is domain plumbing.
