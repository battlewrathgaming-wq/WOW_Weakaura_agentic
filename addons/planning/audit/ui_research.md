_Independent research pass, 2026-08-18. Data only; every claim carries a URL where one was reachable. All sections complete. Unreachable this pass: `github.com/Kioshin/StdUi` (404 — the live repo is `kaminaris/StdUi`), `StdUi.toc` (404 — repo has `StdUi.xml` only), `Bunny67/Details-WotLK/Libs` (404 — libs live under `Details/Libs`); WeakAuras options internals not re-read._

## R1 — per project

### R1.1 Ace3: AceGUI-3.0 + AceConfig-3.0 (Registry / Dialog / Cmd)

- **What.** The reference declarative-options stack for WoW. AceConfigRegistry holds and *validates* an "options table"; AceConfigDialog walks that table and *builds* an AceGUI widget tree from it; AceConfigCmd renders the same table as a slash-command interface. AceGUI is the widget/container/layout layer usable on its own.
- **How UI is described.** One nested Lua table. Root `{ type="group", args={...}, childGroups=, plugins=, handler= }`. Every entry: `type` (`group|execute|input|toggle|range|select|multiselect|color|keybinding|header|description`) plus universal keys `name, desc, order, disabled, hidden, width, icon, iconCoords, handler`, and callbacks `get/set/func/validate/confirm` — "Nearly all parameters can be inherited through the table tree." Type-specific keys: range `min/max/step/bigStep/softMin/softMax/isPercent`; select `values, sorting, style("dropdown"|"radio")`; multiselect `values, tristate`; input `multiline, pattern, usage`; toggle `tristate`; color `hasAlpha`; execute `func, image…`; description `fontSize, image…`; group `args, plugins, childGroups("tree"|"tab"|"select"), inline`. UI-specific overrides: `dialogControl` ("register a custom control with AceGUI and use it in AceConfigDialog"), `guiHidden/cmdHidden/dialogHidden/dropdownHidden`. Source: https://www.wowace.com/projects/ace3/pages/ace-config-3-0-options-tables
- **Schema validation (a checker!).** AceConfigRegistry-3.0 (MINOR 22) carries `basekeys` / `typedkeys` tables of allowed keys per type and a recursive `validate()`; errors are `"AceConfigRegistry-3.0:ValidateOptionsTable(): [path.to.field] - description"`; runs at `RegisterOptionsTable(appName, options, skipValidation)` and lazily on getter calls, cached in `validated[uiType][appName]`. `NotifyChange(appName)` fires `ConfigTableChange` so open dialogs re-render. Source: https://raw.githubusercontent.com/WoWUIDev/Ace3/master/AceConfig-3.0/AceConfigRegistry-3.0/AceConfigRegistry-3.0.lua
- **Widget types (AceGUI-3.0, MINOR 41).** Containers: `Frame` (title + status bar), `Window`, `SimpleGroup`, `InlineGroup` (bordered, `SetTitle`), `ScrollFrame` ("requires parent with Fill layout"), `DropdownGroup` (`SetGroupList/SetGroup`, `OnGroupSelected`), `TabGroup` (`SetTabs/SelectTab`, `OnGroupSelected`), `TreeGroup` (`SetTree/SelectByPath/SelectByValue`), `BlizOptionsGroup`. Controls: `Button, CheckBox (tristate, radio via SetType), ColorPicker, Dropdown (SetList/AddItem/SetMultiselect/SetItemDisabled), EditBox, MultiLineEditBox, Slider (SetSliderValues(min,max,step), SetIsPercent), Heading, Label, InteractiveLabel, Icon, Keybinding`; plus LibSharedMedia `LSM30_*` widgets registered externally. Base API on all widgets: `SetWidth/SetRelativeWidth/SetFullWidth/SetHeight/SetFullHeight, SetCallback, SetUserData, Release`; containers add `AddChild, SetLayout, DoLayout, PauseLayout/ResumeLayout, SetAutoAdjustHeight, ReleaseChildren`. Sources: https://www.wowace.com/projects/ace3/pages/ace-gui-3-0-widgets · https://www.wowace.com/projects/ace3/pages/api/ace-gui-3-0
- **Layout model.** Three registered layouts (`AceGUI:RegisterLayout(name, fn)`): **List** — "Children are stacked on top of each other down the left side"; **Fill** — first child `SetAllPoints(content)`; **Flow** — "A row based flow layout": wraps children into rows against the container's usable width, `width="fill"` forces row break + full width, `relWidth` = fraction of container, row height tracked, container height auto-adjusted unless `noAutoHeight`. Layout is *procedural anchoring at run time* — no constraint solver, no offline model. AceConfigDialog width mapping: default 170px; `"double"`×2, `"half"`÷2, number × 170, `"full"` → `control.width="fill"`. Source: https://raw.githubusercontent.com/WoWUIDev/Ace3/master/AceGUI-3.0/AceGUI-3.0.lua
- **Type→widget mapping (AceConfigDialog MINOR 92).** range→Slider · select→Dropdown (or InlineGroup of radio CheckBoxes when `style="radio"`) · multiselect→InlineGroup of CheckBoxes (or Dropdown w/ multiselect when `dialogControl` given) · toggle→CheckBox · color→ColorPicker · execute→Button (Icon if `image`) · input→EditBox / MultiLineEditBox · keybinding→Keybinding · header→Heading · description→Label; all via `CreateControl(v.dialogControl or v.control, "<default>")`. Groups: `childGroups="tree"` (default)→TreeGroup, `"tab"`→TabGroup, `"select"`→DropdownGroup; `inline=true` groups→InlineGroup embedded in the parent's flow.
- **Visibility.** `hidden`/`disabled` may be boolean, function, or method-name string on `handler`; evaluated per render via `CheckOptionHidden` → `pickfirstset(option.dialogHidden, option.guiHidden)` then inherited `hidden`. Re-evaluated on every refresh (`NotifyChange`, or the dialog's own refresh after a `set`). No dependency tracking: a `hidden` function is simply re-run for every option on every redraw.
- **Per-object dynamic tabs.** Achieved by making `args` a *function* (or rebuilding the table and calling `NotifyChange`), or by registering the whole options table as a function `(uiType, uiName, appName)`. Common pattern in ElvUI/WeakAuras: a loop that writes `args[objectKey] = { type="group", name=obj.name, order=i, args=... }` on each change.
- **3.3.5 status.** Current master `Ace3.toc` Interface line: `11508, 11509, 20505, 20506, 30405, 38002, 40402, 50503, 50504, 120100, 120005, 120007` — i.e. Wrath *Classic* 3.4.x, **not** 3.3.5a. Reading the current sources: AceGUI-3.0.lua core has no post-3.3.5 API references; AceConfigDialog only touches `Settings.RegisterCanvasLayoutCategory` (retail Settings API) inside `AddToBlizOptions` (no `InterfaceOptions_AddCategory` fallback remains), so on 3.3.5 the standalone `Open()` path works and `AddToBlizOptions` must be replaced or the older revision used. Container widgets guard `BackdropTemplateMixin and "BackdropTemplate"` (nil-safe). Practical evidence that Ace3 runs on 3.3.5: the ElvUI-WotLK backport ships Ace3 (see R1.4) and many Warmane-era addons bundle it (e.g. RCLootCouncil-Wotlk repo carries `Libs/AceGUI-3.0/widgets/AceGUIWidget-Keybinding.lua`, https://github.com/andrew6180/RcLootCouncil-Wotlk). Older tagged builds (r700-r1000 era, e.g. "Beta-r701" https://www.curseforge.com/wow/addons/ace3/files/245173) predate the Settings API and are what 3.3.5 packs typically carry.
- **License.** "Limited BSD" (X-License in TOC; LICENSE.txt in repo).
- **URLs.** https://github.com/WoWUIDev/Ace3 · https://www.wowace.com/projects/ace3 · https://www.curseforge.com/wow/addons/ace3

### R1.3 ElvUI config (AceConfig-based) and the ElvUI-WotLK 3.3.5 backport

- **What.** ElvUI's whole options window is one AceConfig options table (`E.Options`), rendered by a *forked* AceConfigDialog. The 3.3.5a backport ("This is the backported version of ElvUI for World of Warcraft - Wrath of the Lich King (3.3.5a)") keeps that architecture. https://github.com/ElvUI-WotLK/ElvUI
- **Where the libs sit.** `ElvUI/Libraries/Ace3` carries AceAddon/Comm/Console/DB/Event/Hook/Locale/Serializer/Timer + CallbackHandler + LibStub; `ElvUI_OptionsUI/Libraries/` carries `Ace3` (AceGUI + AceConfig) and `AceGUI-3.0-SharedMediaWidgets`. Confirmed via GitHub API listings.
- **The fork.** `ElvUI_OptionsUI/Libraries/Ace3/AceConfig-3.0/AceConfigDialog-3.0/AceConfigDialog-3.0.lua`: `local MAJOR, MINOR = "AceConfigDialog-3.0-ElvUI", 79`; `AddToBlizOptions` calls `InterfaceOptions_AddCategory(group.frame)` (the 3.3.5 API); `width_multiplier = 170`; custom controls `"Button-ElvUI"`, `"ColorPicker-ElvUI"`; color `get` may return 8 values ("ElvUI adds e,f,g,h for default color"); a `descStyle` key (inline vs tooltip description); drag-and-drop in multiselect. childGroups tree/tab/select and width handling otherwise upstream. **This file is the concrete "AceConfigDialog that runs on 3.3.5" reference.**
- **How per-object panes are done (Filters.lua).** State variables `selectedFilter/selectedSpell`; a rebuild function nulls and re-creates groups: `E.Options.args.filters.args.filterGroup = nil; ...spellGroup = nil; if selectedFilter == "Debuff Highlight" then E.Options.args.filters.args.filterGroup = {...}`; selectors use `values = function() ... end` (searchable), accessors use `info[#info]` as the key: `get = function(info) return E.global.unitframe.buffwatch[E.myclass][selectedSpell][info[#info]] end`; visibility `disabled = function() return not selectedSpell end`, `hidden = function() return not E.db.unitframe.filters.buffwatch[selectedSpell] end`. https://raw.githubusercontent.com/ElvUI-WotLK/ElvUI/master/ElvUI_OptionsUI/Filters.lua
- **Layout model / widget types.** Inherited from AceConfigDialog (Flow inside groups; TreeGroup left nav; `inline` InlineGroups; `width="full"/"double"/…`).
- **License.** ElvUI is MIT-style ("free to use, modify… must credit"), the backport inherits; check repo LICENSE before embedding.
- **URL.** https://github.com/ElvUI-WotLK/ElvUI · options files listing https://api.github.com/repos/ElvUI-WotLK/ElvUI/contents/ElvUI_OptionsUI

### R1.4 DetailsFramework (`DF:BuildMenu`) and the 3.3.5 backports of Details

- **What.** LibDFramework-1.0 — "a widget toolkit built on Blizzard's native frame API and an optional scaffold for creating self-contained addons"; `BuildMenu` = "Declarative form generation from table definitions supporting toggles, ranges, colors, text entries, and custom types"; a **templates** system ("Reusable visual property tables for fonts, buttons, sliders, and dropdowns"). https://github.com/Tercioo/Details-Framework (retail) · https://github.com/Tercioo/Details-Framework-Classic
- **How UI is described (current upstream, buildmenu.md).** `DF:BuildMenu(parent, menuOptions, xOffset, yOffset, height, useColon, textTemplate, dropdownTemplate, switchTemplate, switchIsCheckbox, sliderTemplate, buttonTemplate, valueChangeHook)`; `menuOptions` is an *array* (order = array order, no `order` key) of `{ type=, get=, set=, name=, desc=, id=, hidden=, disabled=, disableif=fn, min/max/step/usedecimals/thumbscale, values=fn, boxfirst, childrenids, children_follow_enabled, inline, spacement, breakline, text_template, width, height }`; types after alias normalisation: `toggle(switch) · range(slider) · select(dropdown, plus selectfont/selectcolor/selectanchor/selectaudio…) · color · execute(button) · textentry · label(text) · blank(space) · breakline`. Panel-level keys on the array itself: `align_as_pairs, align_as_pairs_string_space (160px), widget_width, widget_height, use_scrollframe, language_addonId, no_refresh_on_change, always_boxfirst, slider_buttons_to_left`. `BuildMenuVolatile` "rebuilds dynamic panels using pooled, reusable widgets". `GetWidgetById(id)` gives a code→widget lookup. https://raw.githubusercontent.com/Tercioo/Details-Framework/master/buildmenu.md
- **Layout model.** Column-flow: widgets are stacked at `(cur_x, cur_y)`, `cur_y -= 20` (or 30 with `spacement`), and when `cur_y < height` or a `breakline` entry is met the cursor jumps to a new column `cur_x = cur_x + max_x + 30`. Fixed widget widths (slider 140×20). No wrap by width, no autosize of parent (except `use_scrollframe`).
- **Visibility.** Upstream: `hidden` skips the row at build time; `disableif` re-evaluated on refresh. **In the 3.3.5 backport (`dversion = 178`, Bunny67/Details-WotLK `Details/Libs/DF/fw.lua`) there is no `hidden` key** — grep of `widget_table.<key>` finds `desc, id, boxfirst, nocombat, spacement, thumbscale, usedecimals, min/max/step, width` only; the loop signature is identical: `function DF:BuildMenu (parent, menu, x_offset, y_offset, height, use_two_points, text_template, dropdown_template, switch_template, switch_is_box, slider_template, button_template, value_change_hook)` and dispatch is `if (widget_table.type == "blank" or widget_table.type == "space") ... elseif (widget_table.type == "label" or ... "text") ... "select"/"dropdown" ... "toggle"/"switch" ... "range"/"slider" ... "color" ... "execute"/"button" ... "textentry"`; `BuildMenuVolatile` exists (line 1115). Combat-lock: `nocombat` widgets go into `disable_on_combat`.
- **3.3.5 status.** Three backports carry DF: https://github.com/Bunny67/Details-WotLK (`Details/Libs/DF`, DetailsFramework-1.0 v178), https://github.com/Kowson/Details-Damage-Meter-for-3.3.5a, https://github.com/fxpw/Details_Sirus. Details-WotLK also bundles the full Ace3 set incl. AceGUI-3.0 + AceConfig-3.0 (another 3.3.5-running Ace3 copy).
- **License.** GNU LGPL 2.1 ("allows embedding in other addons").

### R1.5 TellMeWhen · Bartender4 · Dominos · MDT (config-driven consumers)

- **TellMeWhen (3.3.5 fork, bkader/TellMeWhen_3.3.5).** Single-file addon; options are an AceConfig table: `LibStub("AceConfig-3.0"):RegisterOptionsTable(folder, core.options)` / `core.optionsFrame = ACD:AddToBlizOptions(folder, folder)`. Per-object panes = eight subgroups `group1..group8` written *in a loop at PLAYER_LOGIN* (not via an `args` function); each has toggles + `range` sliders (Scale/Columns/Rows) and conditional entries (Width/Height/Spacing present only when ElvUI is absent — a build-time condition, not `hidden`). Uses `order` for sequence. https://github.com/bkader/TellMeWhen_3.3.5 · https://raw.githubusercontent.com/bkader/TellMeWhen_3.3.5/main/TellMeWhen/TellMeWhen.lua. Modern TellMeWhen (retail/Classic) instead has its own class system: `TMW.C.Config_Panel:New("Frame", name, column, "TellMeWhen_OptionsModuleContainer")`, `StaticConfigPanelInfo{ order, frameKey }` / `LuaConfigPanelInfo` with `GetFrameName()`/`MakePanel()`; panels are XML templates + Lua classes, not an options table. https://github.com/ascott18/TellMeWhen (Options/TellMeWhen_Options.lua, Components/EventHandlers/*/Config.lua). Not on 3.3.5.
- **Bartender4.** AceConfig throughout (options table per bar module, `plugins` for LibDualSpec, `childGroups="tab"` inside bar groups); a 4.4.x line runs on 3.3.5 (Warmane addon lists). Nothing beyond the AceConfig vocabulary. https://www.wowace.com/projects/bartender4
- **Dominos.** Own imperative-but-tabular menu API in `Dominos_Config`: `function Module:OnCreateMenu(menu) self:AddLayoutPanel(menu) ...`, `panel = menu:NewPanel(name)`, `panel:NewCheckButton({ name=, get=, set= })`, `panel:NewSlider({ name=, min=, max=fn, step=, get=, set= })`, font/texture selectors take `{parent, get, set}`. Widgets are appended vertically in call order; no visibility keys in the declaration. https://raw.githubusercontent.com/tullamods/Dominos/main/Dominos_Cast/mirrorTimer.lua. Dominos 1.x ran on 3.3.5 with the same shape.
- **MDT (MythicDungeonTools).** Retail/Classic only; main window is hand-built with AceGUI-3.0 (`AceGUI:Create("Frame")`, embedded `AceGUIWidgets`/`load_widgets.xml`), settings via AceConfig. Illustrates "AceGUI as a widget kit without AceConfig" — the pattern to copy if the option-table shape does not fit (a map/plan editor). https://github.com/Nnoggie/MythicDungeonTools
- **WeakAuras (for completeness).** The largest per-object AceConfig table in the field: options for each aura are *generated* (`WeakAuras.GetDisplayOptions`/`OptionsPrivate` regions add `args` per region type; `hidden = function() return not data.something end` everywhere; `order` numeric floats; `width = WeakAuras.doubleWidth/normalWidth`). A 3.3.5 backport exists: https://github.com/Bunny67/WeakAuras-WotLK (GPL-2.0, last push 2024-06-04, verified via GitHub API). https://github.com/WeakAuras/WeakAuras2 (options internals cited from prior familiarity, not re-read this pass).

### R1.6 WoW XML frame templates as a declarative layer (3.3.5)

- **What the 3.3.5 client accepts** — read from the shipped `Interface/FrameXML/UI.xsd` (3.3.5 UI source mirror https://github.com/andrew6180/WoTLK-3.3.5-UI-Source/blob/master/Interface/FrameXML/UI.xsd; "edited with XMLSpy … by Sam Lantinga (Blizzard Entertainment)"): `LayoutFrameType` has children `Size (AbsDimension|RelDimension) · Anchors/Anchor(point*, relativeTo, relativePoint, x, y | Offset) · Animations` and attributes `name · inherits · virtual · setAllPoints · hidden · parentKey`. `FrameType` adds `TitleRegion · ResizeBounds(minResize/maxResize) · Backdrop(BackgroundInsets/TileSize/EdgeSize/Color) · HitRectInsets · Layers/Layer(level) · Attributes · Frames · Scripts` and attributes `alpha · parent · toplevel · movable · resizable · frameStrata · frameLevel · id · enableMouse · enableKeyboard · clampedToScreen · protected · depth`. `$parent` name substitution. **Present in 3.3.5:** `parentKey` (3 occurrences in the xsd), Animations, Backdrop, Attributes. **Absent in 3.3.5:** `relativeKey`, `mixin`/`secureMixin`, `<KeyValues>`, `intrinsic`, `<Mixins>`, `<ForbiddenAspects>` (0 occurrences) — so a template may name relative frames only by string (`relativeTo="$parentTitle"`), never by key.
- **Templates as data.** `<Frame name="X" virtual="true">` = a reusable spec; `inherits="A, B"` composes; XML is parsed *before* Lua runs (OnLoad only), so **XML cannot express conditions or per-object repetition** — every dynamic pane in the field is Lua-created from tables (AceConfig, DF, StdUi) with XML at most for one virtual template per widget kind. Reference: https://warcraft.wiki.gg/wiki/XML_user_interface · https://wowpedia.fandom.com/wiki/XML_schema · https://addonstudio.org/wiki/WoW:XML_schema
- **Tools generating XML from a spec.** None found in the field. (WoW addon-generators are Lua-side; wowless has `tools/generatexmltest.lua`, which generates XML *test cases* from its schema, not addon UI.)
- **XML linters.** (a) `xmllint --schema UI.xsd file.xml` against the client's own xsd — the 3.3.5 xsd is available (above); wiki: "can sometimes throw errors which are not actually a problem". (b) https://github.com/Meorawr/wow-ui-schema — community UI.xsd, retail-tracking, "intentionally designed to be stricter than what the game actually accepts so as to provide linting capabilities—for example an empty <Frames> element will not validate"; usable via `xsi:schemaLocation` in VS Code / xmllint; **retail schema, so it will reject nothing 3.3.5-specific but will accept post-3.3.5 attributes**. (c) wowless `tools/xmlcontainment.lua` (containment rules per element).

| **wowless** (https://github.com/wowless/wowless, MIT, pushed 2026-08-17, "pre-alpha") | offline, Docker/CMake, headless | Loads TOC/XML/Lua for products `wow, wow_anniversary, wow_classic, wow_classic_era(+ptr), wowt, wowxptr`; simulates events/clicks; **`wowless/render.lua:frames2rects(hframes, product, w, h)`** resolves anchors to rects by topological sort ("`local tt = require('resty.tsort').new()`" … "`rects[r] = { bottom=…, left=…, right=…, top=… }`") and emits `{frames={name, regions={content, name, rect}, strata, strataLevel}}`; `tools/sdlrender.lua` then draws that YAML with SDL from client BLPs — a genuine offline layout+render pipeline | **No 3.3.5 product** — its API/uiobject tables are generated from current client data; retargeting = supplying a 3.3.5 API/uiobject dataset; heavy toolchain |
| **XSD lint** (see R1.6) | offline | Element/attribute well-formedness of XML | No Lua-created frames; no geometry |
| **luacheck + WoW globals** (`.luacheckrc` with `std="lua51"` + WoW globals; used by Ace3/wowless) | offline | Undefined globals, unused vars | Nothing about UI |

Net: **no project in the field ships an offline layout *checker* for 3.3.5** — wowless is the only offline anchor-resolver and it targets current products; every 3.3.5 addon verifies layout by eye or by in-game rect reads.

### R1.8 Outside WoW: declarative UI-from-data in Lua engines (shape only)

The shared shape is **component + props + children**: LÖVE **SUIT** (immediate-mode: `suit.Button("text", {id=, align=}, x,y,w,h)` inside `love.update`, layout via `suit.layout:row(w,h)/col()` — no retained tree, no spec table, https://github.com/vrld/suit); **Nuklear / lua-nuklear** (immediate mode, `nk:layoutRow('dynamic', 30, 2)` then `nk:button('label')`, https://github.com/keharriso/love-nuklear); Roblox **Roact** (retained, React-like: `Roact.createElement("Frame", {Size=UDim2.new(...), Visible=state.x}, { Child = Roact.createElement(...) })` — a spec tree that a reconciler diffs into instances, https://github.com/Roblox/roact) and **Fusion** (`New "Frame" { Size = ..., Visible = Computed(function() return show:get() end), [Children] = {...} }` — properties as a table, reactive `Computed`/`Value` for visibility, https://github.com/dphfox/Fusion). AceConfig sits between: retained spec tree, but visibility is a *polled function* not a reactive binding, and there is no diffing — the dialog releases and rebuilds the widget subtree on every refresh.

## R3 — reusable as-is on 3.3.5 / pattern to copy / does not port

**Reusable as-is on 3.3.5 (lib · version · license):**
- **AceGUI-3.0** (MINOR 41 core reads clean; the ElvUI-WotLK / Details-WotLK copies are proven 3.3.5-running builds) · Limited BSD. Widget kit + Flow/List/Fill layout + `RegisterWidgetType`/`RegisterLayout` extension points.
- **AceConfigRegistry-3.0** (MINOR 22) · Limited BSD — the option-table *schema validator* is standalone Lua (LibStub + CallbackHandler), usable offline under lua51 as a checker for a spec written in AceConfig vocabulary.
- **AceConfigDialog-3.0** — use the **ElvUI-WotLK fork ("AceConfigDialog-3.0-ElvUI", 79)** or a pre-Settings-API revision; current upstream MINOR 92 works for `Open()` but `AddToBlizOptions` calls retail `Settings.*` (no `InterfaceOptions_AddCategory` fallback left). Limited BSD (ElvUI fork inherits ElvUI licence — check).
- **DetailsFramework** DF v178 from Details-WotLK · LGPL 2.1 — `BuildMenu`/`BuildMenuVolatile` + templates + `GetWidgetById`; note no `hidden` at v178.
- **lib-st** (GPL) · **LibQTip-1.0** (Ms-PL) · **LibDBIcon-1.0** (public domain) · **LibDialog-1.0** (All Rights Reserved — embed only if the licence is acceptable) · **LibUIDropDownMenu** (GPLv2) or the Blizzard 3.3.5 `UIDropDownMenu.lua` directly.
- **3.3.5 `UI.xsd`** (Blizzard, redistributed in the 3.3.5 UI-source mirror) for `xmllint --schema` on any XML templates.

**Pattern to copy (not the code):**
1. **One nested table = pane** with `type` on every node and `args`/children — the universal shape (AceConfig, DF, StdUi, Roact/Fusion all agree). Keep `order` numeric with gaps (AceConfig) *or* array order (DF); do not mix.
2. **`hidden`/`disabled` as `bool | function | handler-method-name`, inherited down the tree, polled on refresh** — the field's only visibility model; nobody does dependency tracking. `disableif` (DF) is the same thing renamed.
3. **UI-scoped overrides** (`dialogHidden`, `guiHidden`, `cmdHidden`) — a spec that renders to more than one surface (dialog + slash + your checker) needs a per-surface hide.
4. **`width` as token or multiplier** (`"full"|"double"|"half"|"normal"|number×170`) + **`inline`** for a bordered zone; **`childGroups = "tab"|"tree"|"select"`** for how a group's children are navigated.
5. **Per-object panes = regenerate the subtree and `NotifyChange`** (ElvUI Filters.lua, TellMeWhen loop) or make the subtree a *function*; DF's `BuildMenuVolatile` pools widgets for the same purpose.
6. **`values` as a `{code = label}` map + optional `sorting` array** for the code:user lookup; `name`/`desc` may be functions.
7. **A registry-level validator with `[path.to.field]` error strings** (AceConfigRegistry) — the schema half of a checker; the geometry half is what nobody ships (see R4).
8. **`GetWidgetById(id)`** (DF) / `SetUserData` (AceGUI) — a stable code→widget lookup so a checker can address widgets by spec key, not by frame name.
9. **Templates as data tables** (DF `text_template/dropdown_template/switch_template/slider_template/button_template`) — visual style separated from structure.

**Does not port to 3.3.5:**
- Retail AceConfigDialog `AddToBlizOptions` (Settings API); anything using `BackdropTemplate` unguarded, `C_Timer`, `mixin`/`KeyValues`/`relativeKey` XML, `Settings.*`, `C_AddOns`.
- **StdUi** — retail-targeted, unlicensed on GitHub, no 3.3.5 users found; its 12-column EasyLayout is a *pattern* to read, not a lib to embed.
- **wowless** — no 3.3.5 product data; retargeting means generating a 3.3.5 API/uiobject dataset (large).
- Modern TellMeWhen's `TMW.C.Config_Panel` class system, MDT (retail APIs), Meorawr xsd (retail attributes).

## R4 — layout verification: what exists, what none do

- **Exists, in-game:** rect reads (`GetLeft/GetRight/GetTop/GetBottom/GetRect`, `GetEffectiveScale`) after the frame is shown and `DoLayout` has run — the only ground truth on 3.3.5; FrameStack for identification; DevTool (3.3.5 backport) for table/frame browsing. All are *human-driven*: none emits pass/fail.
- **Exists, offline:** AceConfigRegistry schema validation (keys/types per option type; no geometry). XSD lint for XML (structure; no Lua-built frames). wowless `frames2rects` — topological anchor resolution to `{left,right,top,bottom}` per region and an SDL renderer, **for current-client products only** (`products.yaml`: wow, wow_anniversary, wow_classic, wow_classic_era, …), pre-alpha, MIT.
- **None do:** (a) assert non-overlap / containment / min-size / clipping of a *dynamic* pane before it is shown; (b) verify `hidden` combinations (no tool enumerates the visibility state space — every framework re-runs the functions and looks); (c) check that a `width` token fits the container at the container's actual width; (d) offline layout for 3.3.5 specifically. AceGUI Flow's wrap decisions are computed inside `PerformLayout` at run time and are not exported. **A home-grown `panespec` + `check_rects` that resolves anchors offline for 3.3.5 has no equivalent in the field; the nearest relative is wowless's `frames2rects` (same idea: tsort the `relativeTo` graph, resolve points to screen coordinates, emit rects), which is the one file worth reading for algorithm cross-checks — https://raw.githubusercontent.com/wowless/wowless/main/wowless/render.lua.**

## R5 — vocabulary the field uses

- **Structure:** `type` · `args` (children map, AceConfig) vs positional array (DF, StdUi `rows`) · `group` · `childGroups` (`tree|tab|select`) · `inline` · `plugins` (extension merge into a group's args) · `order` (number or fn; "default = 100, 0=first, -1=last") · `handler` · `name` / `desc` (string or fn) · `icon`/`iconCoords`.
- **Controls:** `execute(func) · input(multiline, pattern, usage) · toggle(tristate) · range(min,max,step,bigStep,softMin,softMax,isPercent) · select(values, sorting, style=dropdown|radio) · multiselect(values, tristate) · color(hasAlpha) · keybinding · header · description(fontSize, image)`; DF aliases `switch/slider/dropdown/button/text/space` and `textentry`, `breakline`, `blank`; StdUi `checkbox/editBox/multiLineBox/dropdown/autocomplete/slider/sliderWithBox/color/button/header/label/texture/panel/scroll/fauxScroll/tab/custom`.
- **Binding:** `get` / `set` / `func` / `validate` / `confirm` (AceConfig, DF); `info[#info]` = current key; `values = function` for live lists; `onChange`/`onValueChanged` (StdUi); `SetHook("OnValueChange")` (DF); `NotifyChange(appName)` (re-render trigger); `ConfigTableChange` callback.
- **Visibility/state:** `hidden` · `disabled` · `dialogHidden` · `guiHidden` · `cmdHidden` · `dropdownHidden` · `disableif` (DF) · `nocombat` (DF) · `childrenids` / `children_follow_enabled` (DF: a toggle governs children's enabled state).
- **Layout:** `width` (`full|double|half|normal|n`) · `SetFullWidth` / `SetRelativeWidth` / `width="fill"` (AceGUI) · layouts `Flow|List|Fill` · `DoLayout / PauseLayout / ResumeLayout / SetAutoAdjustHeight` · `spacement` / `breakline` / `align_as_pairs` / `widget_width` / `use_scrollframe` (DF) · `column` (12-col) / `gutter` / `padding` / `fullSize` / `layoutMargins` (StdUi EasyLayout) · XML `Anchors/Anchor(point, relativeTo, relativePoint, x, y)`, `Size/AbsDimension`, `Layers/Layer(level)`, `inherits`, `virtual`, `parentKey`, `$parent`.
- **Custom controls:** `dialogControl` (AceConfig → `AceGUI:RegisterWidgetType`) · `control` · `custom` + `createFunction` (StdUi) · templates (`text_template`, `dropdown_template`, `switch_template`, `slider_template`, `button_template`; DF).
- **Registry / meta:** `RegisterOptionsTable(appName, options, skipValidation)` · `ValidateOptionsTable` · `AddToBlizOptions` · `Open(appName, container)` · `SetDefaultSize` · `uiType/uiName/appName` (the "which surface is rendering me" triple).
